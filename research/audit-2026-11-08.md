# Repo audit, 8 November 2026

**Status: open.**

A second audit, a day after `audit-2026-11-07.md`, done in the main session with
no subagents. It reads what that audit and the October ones listed as not read,
rather than going over the same files again.

**What this repo does:** mbrd is a moodboard app. You drop pictures, clips,
notes, documents and 3D models on an endless board, and it saves the board as a
`.mbrd` file (a ZIP). The same `web/` code runs as a static website, as a
desktop app (Electron) and as an Android app (Capacitor).

**Load assumed:** one person per install, a few tabs at most. Nothing is shared
between users, so "scale" here means big boards and big drops (hundreds of
files), not many people.

**Checked:** `npm test` passes (3246 tests, 1 skipped). Lint is clean apart from
six warnings, all style. `npm run typecheck` and `desktop/`'s typecheck are
clean. Read: `desktop/updates.ts` in full, the close-and-flush path in
`desktop/main.ts`, Android's `MbrdUpdate`, `MbrdAuth` and `MbrdShell.share`,
`history.ts`, the timeline's restore and file adoption, `merge.ts`,
`import/drop.ts` from `replaceItemFile()` to the end of `importFiles()`,
`import/pur-file.ts`, the board-swap paths in `storage.ts` (`openFile`,
`switchBoard`, `newBoard`, `withFreshAssets`, `mergeBoardFile`), the web
autosave's write and sweep, the size checks in the OFF and PLY readers, and the
release workflow's use of inputs. The updaters, the Android plugins and the
readers hold up: digests are required, names from the page are checked against
an allow-pattern, and every count in a file is checked against the bytes before
anything is allocated.

## Must fix

### 1. An import that is still reading lands on whichever board is open when it finishes (`web/assets/js/import/drop.ts:739-826`)

- **What this is:** `importFiles()` reads every dropped file (hash, thumbnail,
  preview) in a pool of workers, which takes minutes for a big folder, and then
  adds the cards with `addItems()`. The busy strip it shows does not block the
  rest of the app.
- **Problem:** nothing checks that the board is still the same one after the
  read. Drop 200 photos, and while the strip says "Reading 200 files" open
  another board from the library, press New, or open a file. Every board swap
  empties the asset store (`withFreshAssets()` and `newBoard()` in
  `storage/storage.ts`). When the read ends, all 200 cards are added to the
  *new* board, and the ones read before the swap point at files that are no
  longer in the store. They show as missing, and the autosave then reports
  "the board cannot be saved complete" on a board that was never meant to get
  them. The board the files were dropped on never gets them either. The same
  gap is in `importPur()` (`import/pur-file.ts`), `importCanvas()` and
  `mergeBoardFile()` (`storage/storage.ts:837`): each awaits a read, then
  writes to the board it finds.
- **Fix:** a counter that every whole-board load bumps: `let loads = 0` in
  `state.ts`, `loads++` in `loadBoard()`, `export const boardLoads = () => loads`.
  Each of the four callers takes `const at = boardLoads()` before its first
  await, and after its last one does
  `if (boardLoads() !== at) { toast('The board changed while the files were read - nothing was added'); return []; }`.
  About 3 lines in `state.ts` and 2 per caller. Add a case to
  `tests/drop-cap.test.js`: start `importFiles()`, call `loadBoard({})` while
  it reads, and check that nothing was added.
- **If we skip it:** cards land on the wrong board with holes in them, and the
  person loses the drop on the board they meant.

## Should fix

### 2. The desktop updater's version check and digest gate have no test (`desktop/updates.ts:262-271`, `299-340`)

- **What this is:** `newer()` decides whether a release is newer than this copy,
  and `download()` refuses a file with no SHA-256 or a wrong one. Together they
  decide what installs itself on every Windows and Linux copy.
- **Problem:** neither has a test. Android's twin has one
  (`MbrdUpdateTest.java`), and every other pure part of the shell has one
  (`trust.mts`, `atomic.mts`, `backups.mts`, `argv.mts`). `updates.ts` imports
  `electron`, so a test cannot load it. A change that compares versions as text
  or as one decimal would still look right: as text, `"0.1000"` sorts before
  `"0.999"`, and every installed copy stops updating at 0.999 with nothing
  failing.
- **Fix:** move `newer()`, `label()` and the digest pattern into a small
  `desktop/versions.mts`, as `trust.mts` is, and import them back. Test three
  cases: `0.1000` is newer than `0.999`, `0.310.0` equals `0.310`, and a digest
  that is not `sha256:` plus 64 hex characters is refused.
- **If we skip it:** a one-line edit can stop every desktop copy from updating,
  silently.

## Not checked

viewport, the gesture state machine), `state.ts` beyond `addItems()`,
`layout.ts`, `web-route.ts`, `ui/` (except where a link becomes an `href`),
