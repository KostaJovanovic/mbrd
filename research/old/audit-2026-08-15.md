# A whole-codebase audit, 2026-08-15

Open work. Nothing here has been fixed; this is the finding list, and it is a
long one. Written at `fd8bd45` (v0.205), tree clean. The audit began against the
uncommitted working tree that became v0.204 and v0.205, and the two commits
landed mid-run — where a finding was invalidated by them it is marked RESOLVED
rather than deleted, because what the commits fixed is itself worth knowing.

## What this is and how much to trust it

Sixteen readers, one per subsystem, each reading its files in full against the
module headers and the invariants in `CLAUDE.md`, `CONTRIBUTING.md` and
`research/docs/`. Every finding carries a **severity** and a **confidence**, and
the confidence is the part that matters:

- **confirmed** — the reader traced the whole path, and in a dozen cases ran the
  code to see it happen. Several findings below carry a measured number.
- **likely** — the mechanism is read from source and every step checks out, but
  something in the path was not executed.
- **suspicion** — a shape that is wrong, with no demonstrated way to reach it.
  Kept deliberately: the bar for this audit was "everything, including
  suspicions", and a latent hole in a validator is worth a line.

Nothing here was applied to the tree. Two independent claims that contradicted
each other were re-checked by hand and the correction is recorded in place.

## The high tier, ranked

Detail for each is in the per-area sections below.

**Data loss**

1. `storage/mbrd.ts:466` — `parseNote()` strips the `# ` marker `noteMarkdown()`
   deliberately wrote, so the sidecar never matches `flattenNoteRich()` and every
   note is rebuilt from plaintext on an ordinary export→import. Verified by
   running pack→unpack: `align` reset to left and **every `wash` key gone** — the
   highlighter feature `research/docs/mbrd-format.md` documents.
   `tests/mbrd.test.js:395` locks the rebuild in.
2. `main.ts:533` — `flushEdits` is armed before `restoreSession()` finishes. Hide
   or reload the tab during the restore and `autosave()` writes the blank board
   over the snapshot, then the sweep runs `idbDelMany` with an empty `referenced`
   set: **every asset in the cache deleted.**
3. `ui/library.ts:169` — a saved board is deleted permanently on one click of a
   22px `×`. No confirm, no undo, no bin.
4. `storage/storage.ts:825` — a board that lost one asset can no longer be opened
   away from, switched, replaced or exported; the only advertised escape is Clear
   everything.

**Hangs and unbounded allocation**

5. `sticky.ts:382` — `dragRoot()` never terminates on a cyclic `meta.stuckTo`,
   which `seedSticks()` (451) accepts off a file. First press on the note freezes
   the browser. Demonstrated: the Node process had to be killed.
6. `mesh.ts:754`/`:759` — `MAT4` accessors allocate `count × 16` against a
   `count`-only guard. A **356-byte** GLB allocates 366 MiB (measured), and an
   accessor with no `bufferView` pays it once per primitive with no file-size
   bound at all.
7. `import/budget.ts:84` + `drop.ts:743`/`:775` — the pixel budget knows only
   PNG/GIF/WebP/JPEG, and the baked-document and RAW-preview paths skip it
   entirely. A 60-byte BMP declaring 30000×30000 allocates ~3.6 GB.
8. `import/preview.ts:218` — `scanForJpeg()` is O(n²) over 12 MB on the main
   thread, uncapped and uncancellable.
9. `ui/markdown.ts:310` — quadratic backtracking; 200k backticks block the main
   thread **13.7 s, measured**.

**Security**

10. `ui/documents.ts:822` — `scrub()` iterates `node.children` and never the root
    `<svg>`'s own attributes, so `<svg onload=…>` survives into the page. `:837`
    — `style` is on `SVG_OK` and text content is never filtered, so an SVG's
    `<style>` block applies document-wide. Both are live under `tools/serve.py`;
    on the deploy only CSP stops them, so the allow-list `_headers` calls "the
    first lock" is the one that fails.
11. `import/pdf.ts:88` — imports pdf.js from `cdn.jsdelivr.net`, absent from
    `script-src`, and points a worker at it against `worker-src 'self'`. **PDF
    import and viewing are dead on the deploy** and work locally; the catch
    swallows it into a grey card. `tests/csp.test.js` greps only
    `optimize/media.ts`, so nothing catches it.

**Wrong behaviour, user-visible**

12. `canvas/item-dom.ts:396` — `meta.tint` is a number and the guard tests
    `typeof === 'string'`, so `data-tint` is never written: **every sticky note
    on every board renders on sheet 1 and the four-colour pad does nothing.**
    Introduced by `7724374`, present in the shipped bundle.
13. `ui/menu.ts:543` — the Feed's item menu is built for the pressed tile but
    every selection-wide row acts on the canvas selection, which the Feed never
    sets. Long-press tile B, tap Delete, **card A is deleted.**
14. `ui/menu.ts:391` — the capture-phase keydown handler swallows typing whenever
    any panel is up, including a hover flyout that deliberately declined focus.
15. `timeline.ts:856`/`:900` — `goTo()` and `rebuildFrom()` replay the board
    without clearing the undo stacks, so the next Ctrl+Z writes another era's
    geometry onto the current board and marks it dirty.
16. `ui/appearance.ts:754` — the "Every photo" stop makes `sourceCount()` return
    `Infinity`, so `slice(0, Infinity)` mints a blob URL for every picture on the
    board and decodes all of them — what `pictureHashes()`'s header says must
    never happen.
17. `ui/nowplaying.ts:236` — `show()` bails on an unchanged item even when the
    element changed, leaving the bar's listeners on a silenced element.
18. `canvas/stills.ts:148` — frozen-GIF blob URLs are never revoked; the header's
    argument that the node owns the URL is wrong about what a blob URL is.
19. `ui/board-actions.ts:158`/`:450` — an uncaught `autosave()` rejection strands
    Save disabled reading "Saving…" for the session, and makes Restart — the only
    way back on a phone — do nothing.
20. `ui/look.ts:30` — the four `--note-wash-*` tokens are missing from `TOKENS`.
    This is the one failing test, and three separate readers reached it
    independently.

**The test suite** — the part to fix first, because it is what let the rest through
