## Critical

### C1. Web sign-in never finishes (Drive share and sync are dead on the web)

- **Where:** `storage/cloud/oauth.ts:121`, with `REDIRECT_PATH` at `:16`.
- **Failure:** Cloudflare's default `html_handling` answers `/oauth.html` with
  `307 → /oauth` (checked live). Google sends the popup to
  `/oauth.html#access_token=...`, and the popup lands on
  `/oauth#access_token=...`. The poll accepts only an `href` that starts with
  `.../oauth.html`, so it waits until the user closes the popup or until 5
  minutes pass. Share link, Connect and sync cannot start on the web.
- **Fix:** Accept `/oauth` and `/oauth.html` (same origin, pathname matches
  `/\/oauth(\.html)?$/`). The alternative, `"html_handling": "none"` in
  `wrangler.jsonc`, also changes `/patch` and `/privacy`.
- **Confidence:** confirmed (live `curl`).

### C2. One failed shelf write makes the next shelf write a silent no-op

- **Where:** `storage/library.ts:51-72`. The same pattern is at `:102-105` and
  `:118-127`.
- **Failure:** The chain is `writes = writes.then(work, () => {})`. When the
  previous write rejected, only `() => {}` runs, so `work` is skipped and the
  promise resolves. Steps:
  1. `ensureCurrentOnShelf()` fails on quota. The failure goes to
     `console.warn` only.
  2. The user switches board. `shelveCurrent()` calls `putLibraryBoard`, which
     is skipped and resolves.
  3. `switchBoard` loads the other board. The next autosave writes it into the
     session slot. The outgoing board is in no store.
- The same occurs after a failed stash: the user's second try at Open, New or
  Switch succeeds and files nothing.
- **Fix:** `const run = writes.catch(() => {}).then(work); writes =
  run.catch(() => {}); return run;` (the `inTurn()` shape in `storage.ts`).
- **Confidence:** confirmed (script with the same chain shape).

### C3. STEP / BREP: a huge B-spline degree crashes the tab

- **Where:** `mesh/step.ts:553` (`splineCurveOf`), `:451`
  (`splineSurfaceOf`), `mesh/brep.ts:170-190` (`splineAt`).
- **Failure:** No code limits the degree. `splineAt` does degree² work for each
  evaluation. A 606-byte STEP with `B_SPLINE_CURVE_WITH_KNOTS('',100000000,...)`
  ran out of heap after 6 s at 4 GB. Degree 6400 froze the main thread for 18 s.
- **Fix:** Reject a degree above a small constant (32), and require
  `knots.length === ctrl.length + degree + 1`. Throw a plain `MeshError`: this
  is corruption, not size.
- **Confidence:** confirmed.

### C4. IGES: a huge B-spline degree runs a loop of up to 2^53

- **Where:** `mesh/iges.ts:477-485` (`splineCurveOf`), `:338-351`
  (`splineSurfaceOf`).
- **Failure:** The degree `m` is checked only with `Number.isSafeInteger`. The
  loop `for (i < count + m + 1) knots.push(...)` then runs to out of memory.
- **Fix:** The same degree limit as C3.
- **Confidence:** likely (not run).

### C5. TIFF: a 16-byte file with a looping IFD chain hangs the worker until out of memory

- **Where:** `import/tiff-worker.js:165`, with the vendored `UTIF.decode` loop
  at `web/assets/vendor/utif/UTIF.js:93-97`. Also `import/tiff.ts:71-74` and
  `import/heif.ts:156-159`.
- **Failure:** `II 2A00 08000000 0000 08000000` is an IFD with no entries
  whose next pointer points to itself. UTIF pushes objects forever (3.4 GB of
  heap in 5 s in Node). Second part: on timeout, `tiff.ts` rejects but does not
  terminate the worker, so every later TIFF in the session waits behind it and
  fails after 120 s. `heif.ts` has the same timeout shape.
- **Fix:** In the worker, walk the IFD chain with a seen set and a count cap
  before `UTIF.decode`. On timeout, call `w.terminate()` and set
  `worker = null`.
- **Confidence:** confirmed (loop and memory growth); likely (tab crash).

## High

### Storage, sync and data loss

#### H1. Offline start fails: the precached pages are redirected responses

- **Where:** `web/sw.js:19,21,23` (`SHELL`), the fallback at `:106` and
  `:136-146`.
- **Failure:** The deploy answers `./index.html`, `./patch.html` and
  `./privacy.html` with 307 to `/`, `/patch`, `/privacy` (checked live).
  `cache.add` stores a response with `redirected === true`. Offline, the
  navigation fallback gives it to `respondWith()`, and the browser refuses a
  redirected response for a navigation. The app, `/patch` and `/privacy` do not
  load offline. The fake cache in `tests/sw.test.js` does not model redirects.
- **Fix:** Precache `./`, `./patch`, `./privacy` and match those in the
  fallback, or rebuild each redirected response with
  `new Response(res.body, res)` before `cache.put`.
- **Confidence:** confirmed for the redirects; the browser refusal is Fetch
  standard behaviour and was not run in a browser.

#### H2. Opening a cloud board drops its look, grid settings, arrangement and timeline

- **Where:** `storage/storage.ts:553` (`openCloudBoard`).
- **Failure:** `loadBoard(normalizeBoard(pulled.board))` normalises two times.
  The output of `normalizeBoard()` has no `settings`, `arrangement` or
  `timeline`, so the second pass gives defaults. A test gave `gridStep` 77 → 64,
  arrangement `grid` → `spiral`, palette `forest` → `""`, and no timeline. The
  next autosave pushes this board over the remote copy, so the loss reaches
  every machine. Fonts go the same way, and their bytes are then swept.
- **Fix:** `loadBoard(pulled.board)`. `loadBoard` already normalises.
- **Confidence:** confirmed.

#### H3. The shelf trim can delete the board that the user is about to open

- **Where:** `storage/storage.ts:956`, with `switchBoard` at `:1020-1040`.
- **Failure:** With 24 boards on the web shelf, the user opens a file or starts
  a new board, and `ensureCurrentOnShelf` makes 25 rows (it does not trim). The
  user clicks the oldest board. `shelveCurrent()` runs `trimLibrary(24)`, which
  deletes that row and its blob. The user sees "That board is not on the shelf
  any more". On the web that blob was the only copy.
- **Fix:** Protect the switch target in `trimLibrary`, or read the target blob
  before `shelveCurrent()`.
- **Confidence:** confirmed (by reading).

#### H4. After a switch, a reload can show board A under board B's id

- **Where:** `storage/storage.ts:1043-1052` (`switchBoard`),
  `storage/session.ts:256,348`.
- **Failure:** `current-board` changes at once, but the session slot keeps the
  old board until the next autosave. The session record has no board id. If the
  tab closes within about 20 s and the pagehide flush does not complete, a
  reload shows A under id B. The next shelving writes A into B's row, and B's
  only copy is lost. `openFile` and `openCloudBoard` have the same window.
- **Fix:** Store the board id in the session record and compare it with
  `current-board` in `restoreSession()`, or `await autosave()` before
  `setCurrentBoardId`.
- **Confidence:** likely (depends on unload timing).

#### H5. Automatic sync stays off after a reconnect or a manual "Sync now"

- **Where:** `main.ts:620-651`.
- **Failure:** `syncStopped` goes back to false only on `board:load` and
  `board:new`. After the token expires (about one hour), the toast asks the user
  to reconnect. They reconnect, and the panel looks normal, but every later
  autosave returns at `:632`. The other machine opens a stale copy with no
  warning. The same occurs after a conflict that the user resolves with "Sync
  now".
- **Fix:** Clear `syncStopped` after a successful sign-in and after a
  successful manual push.
- **Confidence:** confirmed.

### Timeline and undo

#### H6. A folded run removes its ledger step, and a later Timeline trip deletes a card

- **Where:** `timeline.ts:588`, `history.ts:162`.
- **Failure:** Add B, add A. Move A +10, then -10 (the run folds to nothing and
  its step is removed). Undo two times. Rename B. The "Add" step for A is gone
  from the ledger, but A is on the board. Any Timeline trip
  (`replayTo(timelineAt())`) then removes card A.
- **Fix:** When `place()` pops a folded step, clear `step` on the stack
  entries that carry its id. In `undo()`/`redo()`, move the marker only when
  `steps[at-1].id === cmd.step`.
- **Confidence:** confirmed.

#### H7. A partial undo inside a merged run leaves the ledger with a state the user undid

- **Where:** `history.ts:162`, `timeline.ts` `recordStep()` / `place()`.
- **Failure:** Move A +10 three times (one step). Undo two times (A.x = 10).
  Rename B. A Timeline trip, or save, reload and one undo, puts A at x = 30.
- **Fix:** On an undo that stays inside a run, rewrite the after side of
  `steps[at-1]`, or flag it so `recordStep()` truncates the run first.
- **Confidence:** confirmed.

#### H8. `pendingOp` leaks onto the next unrelated step

- **Where:** `timeline.ts:491`, with `history.ts:65,73` and `layout.ts:953`.
- **Failure:** `declareOp()` sets a value that only `recordStep()` clears.
  Align on cards that are already aligned moves nothing and records nothing, so
  the op stays set. The next "Rename" step carries `op: align` and shows as
  editable. If the user edits that step, the align rule replaces the rename
  delta, and the rename is lost.
- **Fix:** Clear `pendingOp` on every path of `commit()`, in the replay and
  playing branches, and in `rebuildFrom`'s `finally`.
- **Confidence:** confirmed.

### Canvas

#### H9. The spatial index loses very large items

- **Where:** `canvas/spatial.ts:34` (`cellsFor`, `MAX_CELLS = 1024`).
- **Failure:** An item of 12000 × 12000 (legal, `MAX_SIZE` is 20000) needs more
  than 1024 cells, so it is filed under its corner cell only. A query at its
  centre returns `[]`. When the user zooms in on the middle, the item
  disappears. Sticker snap (`wouldStick`/`queryAround`) and `canvas/web.ts:653`
  also miss it.
- **Fix:** Keep oversize items in a separate set that every `queryRect`
  returns, or raise `MAX_CELLS` to cover `MAX_SIZE`.
- **Confidence:** confirmed.

### Desktop shell

#### H10. The renderer can make main trust any path

- **Where:** `desktop/main.ts:1040-1056` (`vouchShelf`), `:938`
  (`store:set`), `desktop/files.ts:28` (`vouch`).
- **Failure:** At boot, main vouches every `path` in `kv/library-index`, and
  the renderer can write that value. A script that finds an XSS in a board
  calls `store.set('kv','library-index',[{path:'...\\Startup\\x.bat'}])`, then
  `relaunch()` (no sender check). After boot, `files.write(path, bytes)` passes
  `checked()`. `files.read` can read any file the same way. This breaks the
  "a renderer cannot name a path" rule in the file headers. `pickImport` also
  vouches each imported picture, so the page can overwrite those files.
- **Fix:** Keep the vouched set in a file that only main writes (dialog
  results, argv, `boards.list`). Keep imported files in a separate read-only
  set.
- **Confidence:** confirmed (by reading).

### Binary readers (a small crafted file freezes or crashes the tab)

#### H11. CFBF: a DIFAT chain that points to itself

- **Where:** `import/cfbf.ts:85-102`.
- **Failure:** A 1024-byte `.doc` / `.xls` / `.max` / `Thumbs.db` with
  header +68 = 0, +72 = 0xFFFFFFFF and sector 0 all zeros. `readCompound` ran
  63 s and used 27 GB RSS. `bakedPreview` runs it on the main thread from
  `drop.ts`.
- **Fix:** A seen set on the DIFAT walk, as `chain()` has, and stop when
  `fatSectors.length` passes `sectors`.
- **Confidence:** confirmed.

#### H12. PE: self-pointing resource directories take N³ time

- **Where:** `import/pe.ts:69-74`, `firstLeaf` at `:185-202`.
- **Failure:** One directory of N RT_ICON entries that all point at offset 0.
  N = 1024 took 15.5 s. A 33 KB file with N = 4096 projects to about 15 minutes
  inside `bakedPreview`.
- **Fix:** One visited-offset set, or one work counter, for each `exeIcon`
  run. Refuse an offset that points to itself or to an ancestor.
- **Confidence:** confirmed.

#### H13. HEIF: one tile named 1024 times, with overlapping extents

- **Where:** `import/heif.ts:348-370`, `payload()` at `:400-423`.
- **Failure:** `MAX_ITEM_BYTES` limits one item, but a grid can name one tile
  1024 times, and each `payload()` call copies it again. A 19 KB `.heic` used
  1.16 GB. A 1 MB file could ask for 64 GB. This runs on the main thread where
  `VideoDecoder` exists.
- **Fix:** A byte total for the whole plan with a cap, and a `payload()` cache
  for each item id.
- **Confidence:** confirmed.

### Mesh readers (a small crafted file freezes or crashes the tab)

All of these run synchronously on the main thread under `parseMesh()`.

#### H14. PLY: an element with no properties loops without end

- **Where:** `mesh/ply.ts:325-337` (binary), `:217-228` (ASCII).
- **Failure:** `element junk 9000000000000` with no `property` lines. The
  loop reads 0 bytes for each element and does not end.
- **Fix:** Reject an element with zero properties and a count above zero
  (plain `MeshError`).
- **Confidence:** confirmed.

#### H15. glTF: a node graph with shared children is walked on every path

- **Where:** `mesh.ts:455-528` (`walkNode`, `addPrimitive`, `readAccessor`).
- **Failure:** `seen` is cleared on the way out, so a node is visited again on
  each path (up to 1,000,000 visits). Each visit reads its accessors again. An
  empty index accessor adds no triangles, so `CAPS.tri` does not stop it. A
  3.6 MB GLB at depth 10 took 6.9 s; depth 20 would take hours.
- **Fix:** Read each accessor or primitive once for each parse. Count the
  elements that `readAccessor` reads against `CAPS.elem` for the whole parse.
- **Confidence:** confirmed.

#### H16. FBX: `CAPS.elem` applies to each array, not to the parse

- **Where:** `mesh/fbx.ts:78`, `:135-150`, `:180`.
- **Failure:** 100 `Geometry` records, each with a zlib-packed 6M-element
  array (4.7 MB file), ran out of memory after 129 s. `Vertices` never count
  toward `CAPS.tri`.
- **Fix:** A running total of unpacked elements for each parse, checked
  against `CAPS.elem`, throwing `Oversize`.
- **Confidence:** confirmed.

#### H17. XML: the attribute regex backtracks quadratically (AMF, 3MF, Collada)

- **Where:** `mesh/xml.ts:132` (`ATTR` in `readAttrs`).
- **Failure:** `<amf><a xxxx…(160,000 x)/></amf>` (160 KB) froze the main
  thread for 15.6 s.
- **Fix:** A manual attribute scanner, or find `=` with `indexOf` first.
- **Confidence:** confirmed.

#### H18. ASCII FBX: the `grab` regexes scan to the end of the file for each hit

- **Where:** `mesh/fbx.ts:415-416`.
- **Failure:** `'Vertices: *1 { a: '.repeat(40000)` (720 KB) froze the main
  thread for 28.9 s.
- **Fix:** Find `{` and `}` with `indexOf`, and stop when no `}` remains.
- **Confidence:** confirmed.

#### H19. STEP: bare words with no separators cost O(n²)

- **Where:** `mesh/step.ts:228-237` (`readValue`).
- **Failure:** `#1=X(A A A … 80,000 times);` (160 KB) froze the main thread
  for 42 s. The JS reader gets this file because the kernel rejects it.
- **Fix:** Stop the token scan at white space, or slice only after the token
  kind is known.
- **Confidence:** confirmed.

#### H20. AMF: nested constellations fan out exponentially

- **Where:** `mesh/amf.ts:23-44` (`emit`).
- **Failure:** `MAX_INSTANCE_DEPTH` (32) limits depth, not visits. Leaves with
  no geometry never reach `CAPS.tri`. A 2.2 KB chain of 24 levels with 2
  instances each took 1.56 s; depth 32 would take about 7 minutes.
- **Fix:** Count visits in `emit` and throw `MeshError` past a limit, as the
  glTF walk does with `MAX_NODE_VISITS`.
- **Confidence:** confirmed.

#### H21. STEP and IGES: composite curves fan out exponentially

- **Where:** `mesh/step.ts:494-509`, `mesh/iges.ts:454-466`.
- **Failure:** Each segment is evaluated again, with no memo. STEP has no depth
  limit. A 2.7 KB STEP chain of 22 levels took 2.66 s; 30 levels would take
  about 11 minutes.
- **Fix:** Memoize `curveOf` by entity id, and add a depth and a visit limit.
- **Confidence:** confirmed (STEP); likely (IGES).
