# Full refactor plan, 2026-10-08

Living plan for a full refactor of mbrd. The audit workflow's verified findings are added below as an "Audit" section when it finishes, and the phases are revised from them here.

## Context

Nothing is broken. The codebase hasn't been refactored in a long time, many features have been added since, and a large share was written by Opus 5, whose quality is doubtful. The goal is a cleaner, smaller codebase that does the same thing.

- **Allowed:** small bug fixes along the way. No new features.
- **In scope:** everything: web/ TypeScript, CSS, the desktop and mobile shells, tooling and tests.
- **How it lands:** many small commits on `main` through `save.bat quick-commit`, one sequential stream, never pushed by the agent.

Survey numbers:

- 237 TS files, about 116k lines; 27 CSS sheets, 19.8k lines.
- About 31% of lines are comments (51% in `canvas/input.ts`), with 455 comments that narrate history.
- 51 exports are never used outside their file.
- 26 late-bound setter slots.
- Byte readers are duplicated (`le32` five times, `bytes` four times).
- `ui/` is 67 flat files.
- The root is both the floor (`state.ts`, `layout.ts`) and the ceiling (`main.ts`, `commands.ts`).
- `architecture.md` is stale.

## Step 0: small requests before the refactor

1. **Patch-page footer:** drop the version from "mbrd 0.688 by valjdakosta". The template is `tools/gen-patch-page.mjs:366`; regenerate `web/patch.html` afterwards.
2. **Em dashes** in visible UI text and in docs. Each one is rewritten by context (comma, colon, parentheses, full stop or hyphen), never swapped mechanically.
   - **Docs:** `CLAUDE.md`, `.github/CONTRIBUTING.md`, `.github/THIRD-PARTY.md`, `research/docs/*.md`, `research/*.md`.
   - **UI text:** strings users see in `web/assets/js/**`, `web/*.html`, `desktop/` and `mobile/`.
   - **Left alone:** code comments, CSS, markup nobody sees, `katex.mjs`, `research/old/` and `patch-notes.md`.
   - **Check:** if an inline `<script>` in `index.html` changes, update the hashes in `web/_headers`.

## Fixed constraints

**Must stay compatible:**

- **`.mbrd` files.** Every existing board opens; any schema change needs a migration.
- **Release file names.** Installed updaters read them.
- **`window.mbrd`.** Its nine keys stay.
- **Stored settings and session state.** Keys may be renamed only with a migration in `prefs.ts` / `idb.ts`. `desktop/chrome/look.ts` repeats three of those key literals, so they change together.

**Open to change:**

- Folder layout, the layering graph and the core abstractions.
- The single-menu rule.
- The guard tests themselves. They are mostly valuable, so prune lightly.

**Fixed:**

- `canvas/input.ts` stays one file. It gets fewer comments; its structure stays.
- `npm test` stays zero-install.
- The hand-rolled binary readers stay. Only their helpers are deduplicated, and the mesh readers stay synchronous.
- `Oversize` and plain `Error` stay distinct (`consent.ts`).

**Conventions:**

- **Comments:** keep the 2-5 line module header; inline comments only for a non-obvious WHY. Load-bearing history moves to `research/docs/*`; the rest of the narration is deleted.
- **Spelling:** British `colour` in all names (files, symbols, CSS classes), but never in web APIs or format tokens.
- **Exports:** those that exist only for tests are allowed. Exports nobody uses are deleted.
- **Dead or half-finished features:** listed for the owner to decide each time. Never deleted unasked.
- **Commits:** short and prefixed, e.g. `refactor(canvas): merge zoom-about helpers`. `patch-notes.md` gets one summary line at the end, written by the owner.
- **Verification:** on the phone over adb: the web app in Chrome over CDP, plus an APK build and install at milestones.

## Phase 0: safety net, before any code moves

1. **Browser suite.**
   - Playwright 1.63 from `desktop/node_modules`, with the Chromium, Firefox and WebKit already installed.
   - Lives in a new `tests-browser/`, outside `tests/`, so `npm test` stays zero-install.
   - Reuses the static server and boot wait from `tools/smoke.mjs`, and drives the app through `window.mbrd.cmds`.
   - **Coverage:**
     - Canvas gestures: pan, zoom, drag, marquee, resize, connections.
     - Save, refresh and recover, plus a `.mbrd` export/import round trip.
     - File imports: image, video, PDF, 3D, PureRef.
     - Every menu opens and every setting applies.
     - A touch project under Chromium mobile emulation.
   - **Priorities from the canvas audit:**
     - Move slop, snap and the Alt-copy fold.
     - Resize grips.
     - Pinch with finger-count changes.
     - Right-press pan versus the context menu.
     - Wheel classification and zoom-about-cursor.
     - The Escape chain.
     - Nudge folding into one undo step.
     - Cull and remount keeping state, then a board reload.
     - Note composer and overflow.
2. **Running it.** `npm run test:browser`, locally and only when asked. It is not run on every commit and not in CI; CI keeps `smoke.mjs`.
3. **Baseline.** All existing legs green. Baseline screenshots are recorded for visual comparison at milestones, and a few current boards are exported as `.mbrd` fixtures to reopen after each phase.

**Status, 2026-10-10:** the suite is built: 116 tests in seven specs, 109 passing and 7 skipped. The skips are two known bugs marked `fixme` and two engine limits.

- **Specs:** `gestures`, `board`, `persistence`, `imports`, `menus`, `settings`, `touch`.
- **Shared code:** the static server moved out of `smoke.mjs` into `tools/web-server.mjs`, and the PureRef writer out of `tests/pureref.test.js` into `tests/pur-builder.js`.
- **Engine limits:**
  - Playwright's Windows WebKit cannot store a Blob in IndexedDB, so `persistence` skips WebKit.
  - WebKit has no `canvas.captureStream`, so the video import skips there.
  - Chromium export goes through `showSaveFilePicker`, which a test cannot answer. `persistence` deletes the pickers and takes the download path Firefox and Safari use.
- **Still to do:** the screenshot baseline and the `.mbrd` fixtures from step 3.

## Phase 1: audit

- **Agents:** one read-only auditor per area (18 areas), each finding checked by an adversarial verifier, then a synthesis plus a completeness critic. No agent spawns further agents.
- **What they hunt for:** dead code, verbose or historical comments, duplication, over-engineering, stale docs, colour/color naming, and bugs seen in passing.
- **What each module gets:** a mess score plus concrete findings.
- **Results:** added below, ranked worst-first, with a "features to decide" list for the owner.
- **End of phase:** a go/no-go review with the owner, which also settles the `ui/` grouping.

## Phase 2: mechanical cleanup, low risk, many files

- **Unused exports:** delete them after checking each with Grep. The `DEFAULT_SETTINGS.axes` and `gridStyle` keys stay readable in `.mbrd` files.
- **Byte helpers:** deduplicate them into one module the readers share (`le16`, `le32`, `be32`, `bytes`, `ascii`, `latin1`, `syncsafe`, `extOf`). Use `util.ts`'s `clamp`, and share the `frame`/`sleep` helpers.
- **Comments:** trim module by module, worst-first.
- **Duplicated lists:** generate them from one source. The build writes `404.html` and the `SHELL` CSS list in `sw.js` from `index.html`, which retires `notfound` and parts of `css-order` and `sw`. `save.bat` calls the generator.
- **Test consolidation,** with no new dependencies:
  - The seven vendor-pin tests become one table-driven test.
  - The four CSS-token tests become one.
  - Source-text tests stay alongside the browser suite.

**Status, 2026-10-10.** Everything above is done except comment trimming:

- **Exports (v0.693):** four dead ones deleted, 91 un-exported. `HEIC2ANY_VERSION` and `initGrimeLab` stay; both have readers outside their file.
- **Byte helpers (v0.694):** `web/assets/js/bytes.ts` holds them, in the layer test's base set. `heif.ts` keeps its own `u8`/`u16`/`u32`/`str`, which return 0 past the end instead of reading garbage, a different contract. `extOf` and `clamp` now come from `util.ts` everywhere. `frame`/`sleep` turned out to live only in `ui/capture.ts`, so there was nothing to share.
- **Vendor tests (v0.695):** `tests/vendor.test.js`, one row per library, nine rows, heic2any among them, which had no test before. Each row is held to THIRD-PARTY.md, which pdf.js, onnxruntime and occt were not before.
- **CSS tokens (v0.696):** `tests/css-tokens.test.js` replaces `font-tokens`, `type-scale`, `stacking` and `spacing`.
- **Generated lists (v0.697):** `tools/gen-shell.mjs` writes `404.html` and the stylesheet block of `SHELL`, between two markers, and `save.bat` runs it. `APP_CSS_ORDER` is read from `index.html`, so a new sheet is one `<link>`. `notfound.test.js` stays as the freshness check for `404.html`, and `css-order.test.js` is now the one for `SHELL`. The service-worker cache list changed only in order: `fonts.css` moved up into the generated block.

## Phase 3: layout rethink

**Target layout for `web/assets/js`:**

- **`core/`:** today's BASE set (`board-model`, `board-store`, `history`, `geometry`, `layout`, `timeline`, `util`, `prefs`, `notify`, `consent` and the rest). `state.ts` dissolves into focused modules.
- **`app/`:** `main.ts` and its wiring.
- **`commands/`:** `commands.ts` moves in, as `commands/index.ts`.
- **`mesh/`:** `mesh.ts` moves in.
- **Kept:** `canvas/`, `import/`, `storage/`, and `ui/` (grouped per the audit).
- **`optimize/`:** given a rank in the layering.
- **Folded away:** `media/` and `stickers/` go into neighbouring folders.

**Rules for the move:**

- **Layer test:** `tests/layers.test.js` reads tiers from folders instead of the hand-written BASE list. Its DEBT map stays empty.
- **Imports:** symbols are imported from the module that defines them; the `state.ts` re-export facade goes.
- **Setter slots:** removed where the new layout fixes the dependency direction. Injection stays only where it keeps a module loadable without a DOM in tests (`setOverlays`, `setRiskPrompt`, `setAssetNameLookup`, `setNoteMenu`).
- **Renames:** `color*` becomes `colour*` (`color.ts`, `ui/color-picker.ts`, `ui/legacy-color.ts`, CSS classes).
- **Lazy loading:** `ui/clean/` and `perf/` load with a dynamic `import()` on first use. `window.mbrd.perf` keeps its shape.
- **Commits:** each move is its own commit, with every import updated and paths matching file case exactly.

## Audit

Pending: the 18-area workflow is still running. Three earlier read-only surveys (root and small folders, `canvas/`, `import/` + `mesh/` + `storage/` + `optimize/`) are already in. The bugs they found are below.

**Binary readers:**

- **The "lift" prompt fires on corrupt files.** `mesh/off.ts:37`, the ASCII path in `mesh/ply.ts:181`, and `mesh/fbx.ts:81` raise `Oversize` before the corruption check. A corrupt file is therefore offered a lift before it fails.
- **Allocation before the bounds check.** `mesh.ts:605` `readAccessor` allocates first. The ASCII STL reader (`mesh.ts:224`) builds every facet string before its cap.
- **No byte ceiling before reading a whole TIFF:** `import/tiff.ts:41`.
- **libarchive retries files the hand reader called corrupt:** `import/archive.ts:102`.
- **The two ZIP readers disagree** on name decoding (CP437) and on duplicate-offset checks (`mesh/zip.ts` vs `storage/zip.ts`).

**Behaviour:**

- **Middle press during a left drag** pans over the move and never commits it (`canvas/input.ts:1438`).
- **Module state survives a board reload.** `resetItems` leaves state such as `liftedIds` behind.
- **`hashText` separator** is the no-op `hash ^= 0`, so `("ab","c")` hashes the same as `("a","bc")` (`timeline.ts:1207`). Fixing it changes stored fingerprints, so it needs a migration decision.
- **Wrong number in the oversize message:** `mesh/occt.ts:116` reports the ceiling as the model's triangle count.
- **Undo is bypassed.** `adoptAspect` (`canvas/renderers.ts:2293`) and `growNote` (`canvas/notes.ts`) mutate live items without undo.

**Found while building the browser suite:**

- **Not an app bug: Playwright's Firefox loses one hover.** In the menu for a multiple selection, "Select" never opens its submenu there: a `pointerleave` from the whole menu follows the row's `pointerenter` by 3 ms. A real Firefox opens it (the owner checked), so `menus.spec.js` skips that case in Firefox.
- **The panel's pickers carry no `aria-haspopup`.** Every picker opens a menu, but nothing tells assistive tech so, unlike the toolbar flyouts (`ui/panel.ts` builds them).
- **Dynamic is a no-op on a board with no pictures.** The palette picker reads "Papyrus" while the look is already automatic and waiting for photos, so choosing Dynamic changes nothing.
- **`cmds.newBoard` is not a new board.** It makes a board inside this one; a new board is `cmds.new`. Two names one word apart for different things.
- **Checked and sound:**
  - A finger lifted and put back mid-pinch re-seats the pinch; nothing jumps.
- **Fixed: Rearrange under the title hung a disc by its point.** With "keep cards below the title card", a spiral or scatter was laid out whole and hung by its rounded top, a cone under the title. `arrange()` now takes `flatTop`. The spiral skips the golden angles that land in the cap above it, and the scatter redraws them. The block-shaped layouts already had flat tops.
  - **Second fix (v0.700–v0.701): which way is up.** The board's y runs up and layout space runs it down. v0.700 misread a probe drawn upside down and moved the cut to the bottom; v0.701 mirrors cut layouts (`flatSide()`) so the flat edge is on top. The unit test and the browser test now count the cards flush with the top, and the browser test also requires more of them than at the bottom. It fails if the bug is put back.
  - **Now:** the cut is at 0.65 of the radius, so the top is about 76% of the widest row. `liftToCut()` raises the cards just under it, and the cards beneath them, so the top row sits flush on the cut without leaving a gap. The scatter disc grows by the area of the cap it loses.
  - **The test:** it counts the cards flush with the top. Uncut discs have 1 or 2, cut ones have 3 to 6.
