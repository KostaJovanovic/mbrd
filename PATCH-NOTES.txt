mbrd - what changed

Everything done in this session, on top of v0.92. Not yet pushed, and not yet
exercised in a browser.


THE BOARD MOVES MORE SMOOTHLY

- Three things the board was doing on every single frame of a pan or a zoom,
  whether or not they made any difference to what you see.

- `Faster` Editing a sticky note no longer drags the whole board down. While a
  note was open for editing, its little toolbar re-measured itself four times
  per frame, and it did so at the worst possible moment - just after the board
  had moved - which forced the browser to recalculate the entire page's layout,
  sixty times a second, for as long as the note was open. It now works out where
  to sit from what the board already knows, and measures nothing.

- `Faster` The grid stops redrawing when nothing has moved. The dotted grid is
  painted afresh on every view change, including the many that move it by less
  than a single pixel - the tail of a flicked pan as it settles, and a trackpad
  or precision mouse handing over zoom in fractions too small to see. Those are
  now skipped.

- `Faster` Zooming out does less work per frame. Zooming out re-checks every card
  on screen to see what has left the view, on every frame, for the whole gesture.
  That check now runs about eight times a second during the movement and once
  more the moment you stop. Deliberately a throttle and not a skip: skipping it
  entirely lets a long pan across a big board pile up cards it never lets go of,
  which is the exact problem the check exists to prevent.


SAVING, EXPORTING AND REOPENING ARE LIGHTER

- Saving, exporting and reopening a heavy board are all markedly lighter - a
  board full of video no longer has to fit in memory twice to be written to a
  file, and a board full of photographs opens without hundreds of separate trips
  to the browser's storage.

- `Faster` Exporting a big board no longer holds it twice over. Writing a .mbrd
  used to read every photo, video and sound file into memory, and then hold a
  second copy of each while the archive was assembled - so a board a browser
  could comfortably display was not necessarily one it could save. The file is
  now written straight from the pictures where they already sit, a piece at a
  time, and streamed to disk. What it costs to write a board no longer depends
  on how big the board is.

- `Faster` Saving and reopening a photo-heavy board is much quicker. The
  background save used to make one separate trip to the browser's storage per
  picture, waiting for each before starting the next - five hundred photographs
  meant five hundred round trips, once between you and a board you had been told
  was safe, and again between opening the tab and seeing anything. Those are now
  grouped, with the reopen still counting its progress so the wait stays
  explicable.

- `Faster` Dragging a colour stops writing to disk sixty times a second. Moving a
  colour picker saved your whole look to browser storage on every single frame of
  the drag - a blocking write, on the same thread as the picture you were
  watching. It now saves about five times a second, still keeping up, and always
  writes once more on the way out so nothing is lost if you close the tab
  mid-drag.


FOUR FAULTS CLOSED

- The save script refuses to ship a broken board, and three quiet faults behind
  it are closed - one of which could leave a picture from a board you had already
  closed.

- `Fix` Saving refuses a half-finished merge. After a pull that hit conflicts,
  running the save script would have staged the files still carrying conflict
  markers, told the version control the conflicts were settled, and committed -
  and possibly pushed - an application that no browser and no test could read. It
  now stops and names the files that still need attention, before anything is
  written.

- `Fix` A picture from the old board can no longer reappear on the new one. mbrd
  makes a screen-sized copy of every photograph in the background. If you opened
  a different board - or moved the sharpness dial - while one of those was still
  being made, the finished copy would arrive afterwards and quietly file itself,
  leaving a picture belonging to a board that was no longer open, at a sharpness
  nobody had asked for.

- `Fix` Undo no longer holds on to more than it should. The history remembered
  its last two hundred actions and counted them all the same, so nudging two
  cards and nudging ten thousand cost the same one slot - while the second
  quietly held two copies of the whole board's positions. On a big board that
  added up to the same geometry stored twenty times over, in a history nobody
  walks back that far. Heavy actions now declare their true cost and are let go
  of sooner. The one thing never dropped is a single action bigger than the whole
  budget, which is precisely the one you are most likely to want back.

- `Fix` A blocked database connection is cleaned up. When another tab held the
  board storage open, mbrd reported the failure but left the connection that
  arrived afterwards open with nobody holding it - and an idle connection like
  that is itself what blocks the next tab.

- `Fix` The development server answers awkward addresses properly. A request
  naming a different drive made the local dev server's request handler fail
  outright and drop the connection, instead of answering with a plain "not
  found".


UNDER THE HOOD

- Maintenance - the central file is now seven. state.js went from 3,202 lines to
  1,806 - down 44% - as the bus and the dirty flag, the board's own shape, the
  undo engine, sticky-note relations, the two layouts and the Mobile pack, and
  the front-to-back card order each moved into a file of their own. Nothing that
  used it had to change: every name is still available exactly where it always
  was.

- Maintenance - the thread graph behind the cards moved out of the file that
  draws it. canvas/web.js went from 1,028 lines to 513 and now only draws; the
  algorithm that decides which cards get a thread, and the governor that decides
  how many a given machine can afford, live on their own where they can be tested
  without a browser at all.

- Maintenance - every settings row in the panel is now built by one shared
  builder rather than hand-assembled in four separate files, which is what stops
  the fifth one from being subtly wrong.

- Maintenance - the research folder was triaged, with finished work archived and
  the live plans given an accurate account of what is actually built.


TWO THINGS DELIBERATELY NOT BUILT

- A level-of-detail proxy for far zoom, and a memory ceiling behind it, are both
  written up and left alone. The plan that calls for them gates both on a reading
  taken on the iPhone that crashes, the fixes that would change that reading have
  all since landed, and the measurement has never been taken. Building either
  against no measurement is how a regression ships.


NOT YET CHECKED IN A BROWSER

- All of the above passes the full test suite - 697 tests, up from 577 at the
  start - but the suite deliberately does not cover turning the settings table
  into actual controls, and a good deal of this touches the canvas, the storage
  layer and the app's central file. The sidebar, the Look tab, the Mobile
  masthead, save and open, refresh recovery and pan/zoom all want exercising
  before this is trusted.
